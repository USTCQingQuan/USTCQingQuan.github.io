# 拾学集 · AI 检索接入指南

> 目标：让同学用**自然语言**提问（如"我想找数学分析的复习资料"），由 AI 从 170 条资源里
> 挑出合适的并说明理由。
>
> **为什么不用向量检索（RAG）**：DeepSeek 官方明确不提供 embedding 接口
> （见 [DeepSeek-V3 issue #806](https://github.com/deepseek-ai/DeepSeek-V3/issues/806)，
> 调用 `/embeddings` 返回 404）。而拾学集只有 170 条资源，全部塞进提示词也只占约 1.5 万 token，
> DeepSeek 的上下文窗口是 1M —— **根本不需要向量库**。少一个组件，就少一处故障。

## 一、成本（按官方定价实算）

DeepSeek `deepseek-flash` 价格（[官方定价页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)）：

| 时段 | 输入（缓存未命中） | 输入（**缓存命中**） | 输出 |
|---|---|---|---|
| 高峰（工作日 9:00-12:00、14:00-18:00） | 2 元/百万 | **0.04 元/百万** | 8 元/百万 |
| 空闲（其余时段含周末） | 1 元/百万 | 0.02 元/百万 | 4 元/百万 |

**本项目的实测数据**：提示词约 15,280 token，回答约 300 token。

| 场景 | 单次成本 |
|---|---|
| 首次（缓存未命中，高峰） | 约 **3.3 分** |
| 后续（缓存命中，高峰） | 约 **0.3 分** |
| 后续（缓存命中，空闲） | 约 **0.15 分** |

**一天 100 次提问 ≈ 0.3 元。** 充值 10 元可以用很久。

> 缓存能生效的前提：**系统提示词保持完全一致**。所以提示词是生成一次、固定不动的文件，
> 不要每次请求动态拼接（比如带上当前时间、随机数），那会让缓存永远失效、成本涨 50 倍。

## 二、架构

```
用户提问
   ↓
前端 index.html（「问 AI」入口）
   ↓  POST { question }
云函数 cloudbase/ask（API Key 只存在这里的环境变量中）
   ↓
系统提示词（固定，170 条资源）+ 用户问题 → DeepSeek /chat/completions
   ↓  返回 { answer, resources:[{title, reason}] }
★ 云函数校验：标题必须真实存在于资源库，否则丢弃
   ↓
前端渲染：自然语言回答 + 可点击的资源卡片
```

**★ 那一行是整个方案的安全底线**：即使模型编造了一个不存在的资源，
它也会在服务端被过滤掉，永远到不了用户眼前。

## 三、部署步骤

### 1. 注册 DeepSeek 并充值

1. 打开 https://platform.deepseek.com/
2. 手机号注册 → 实名认证
3. 充值（10 元足够）
4. 创建 API Key → **复制下来，只显示一次**

> ⚠️ **不要把 API Key 发给我，也不要写进任何会提交到 git 的文件。**
> 它只需要填进云函数的环境变量。

### 2. 注册腾讯云并开通 CloudBase

1. 打开 https://cloud.tencent.com/ → 注册（手机号 + 实名）
2. 进入「云开发 CloudBase」控制台 → 新建环境（选**按量计费**，有免费额度）
3. 记下**环境 ID**（形如 `shixueji-3g8xxxxx`）

### 3. 部署云函数

在 CloudBase 控制台 → 云函数 → 新建云函数：

| 配置项 | 值 |
|---|---|
| 函数名称 | `ask` |
| 运行环境 | Node.js 18 或更高 |
| 内存 | 256 MB |
| 超时时间 | **20 秒**（调用大模型需要时间，默认 3 秒会超时） |
| 入口函数 | `index.main` |

然后把本仓库 `cloudbase/ask/` 目录下的 **4 个文件**全部上传：

```
index.js         云函数代码
ai-prompt.txt    系统提示词（由 tools/build-ai-prompt.mjs 生成）
resources.json   资源库（用于校验 AI 返回的标题）
package.json     CommonJS 声明
```

**最后配置环境变量**（云函数 → 配置 → 环境变量）：

| 变量名 | 值 |
|---|---|
| `DEEPSEEK_API_KEY` | 你的 API Key |

### 4. 生成 HTTP 访问地址

云函数 → 触发方式 → 新增「HTTP 访问服务」→ 得到形如：

```
https://shixueji-3g8xxxxx.service.tcloudbase.com/ask
```

**把这个地址发我**，我接前端。

## 四、资源库更新后要做什么

资源库改动后，提示词会失效（缓存也失效）。重新生成并上传即可：

```bash
node tools/build-ai-prompt.mjs resources.json ai-prompt.txt
copy resources.json cloudbase\ask\resources.json
copy ai-prompt.txt cloudbase\ask\ai-prompt.txt
```

然后重新上传这两个文件到云函数。

> 建议把这一步加进发布流程：**改了 `resources.json` 就重新生成提示词**，
> 否则 AI 会看不到新资源，甚至推荐已经被删掉的资源。

## 五、本地能验证什么（不需要账号）

```bash
npm test
```

包含 `tests/verify-ai-guard.mjs`，用 mock 数据验证云函数的核心逻辑：

| 测试 | 验证内容 |
|---|---|
| 正常返回 | 真实资源被保留，URL 自动补全 |
| **★ 防幻觉** | AI 编造的 3 条资源全部被丢弃 |
| 资源库没有 | 如实说明"暂时没有"，不硬凑 |
| 标题空格 | 前后空格 trim 后能匹配 |
| 重复推荐 | 自动去重 |
| 异常输入 | 非 JSON / 缺字段 / 空回答都不会崩溃 |

**这些都不需要 API Key 就能跑**，所以每次改代码都能立刻验证防护是否还生效。
